# প্রতারক চেক (Protarok Check)

বাংলাদেশের জন্য প্রতারণার নম্বর যাচাইয়ের ওয়েবসাইট — টাকা পাঠানোর আগে নম্বর যাচাই,
প্রমাণসহ রিপোর্ট, মডারেশন-ভিত্তিক প্রকাশ, আপত্তি/সংশোধন ব্যবস্থা।

## পেজসমূহ
- `/` — নম্বর যাচাই (ফ্রি, সাইনআপ ছাড়া), পরিসংখ্যান, সাম্প্রতিক যাচাইকৃত অভিযোগ
- `/report` — প্রমাণসহ (TrxID/স্ক্রিনশট) রিপোর্ট জমা — মডারেশন ছাড়া প্রকাশ হয় না
- `/number/<নম্বর>` — একটি নম্বরের পূর্ণ প্রোফাইল (ঝুঁকি + সব যাচাইকৃত অভিযোগ)
- `/objection` — নম্বরের মালিকের আপত্তি; জমা পড়লেই প্রোফাইল "পর্যালোচনাধীন"
- `/disclaimer` — নীতিমালা (অভিযোগ ≠ অপরাধ প্রমাণ; প্রমাণ-নীতি; গোপনীয়তা)
- `/admin` — মডারেশন কিউ (পাসওয়ার্ড: ADMIN_PASSWORD)

## গোপনীয়তা নকশা
- রিপোর্টারের নম্বর/প্রমাণ কোনো পাবলিক API-তে কখনো পাঠানো হয় না
- পাবলিক তালিকায় নম্বর আংশিক ঢাকা (017****678); পূর্ণ তথ্য শুধু নির্দিষ্ট নম্বর খুঁজলে
- রিস্ক লেভেল: ০ = কোনো অভিযোগ নেই · ১–২ = সতর্ক · ৩+ = উচ্চ ঝুঁকি · আপত্তি খোলা থাকলে = পর্যালোচনাধীন

## টেক স্ট্যাক
Next.js 14 + Prisma + PostgreSQL (Supabase) — Vercel-এ হোস্টিং।

## ডিপ্লয় (৩ ধাপ)
1. **Supabase:** SQL Editor-এ `create_tables.sql` চালান। তারপর Settings → Database থেকে
   Transaction pooler URI (port 6543, `?pgbouncer=true&connection_limit=1`) নিন।
2. **GitHub:** এই রিপোটি push করুন।
3. **Vercel:** রিপো Import করুন। Environment Variables:
   - `DATABASE_URL` = pooler URI
   - `ADMIN_PASSWORD` = মডারেশন প্যানেলের পাসওয়ার্ড (নিজে ঠিক করুন)
   Build command: `prisma generate && next build` (package.json-এ সেট করা আছে)।

## লঞ্চের আগে
- সিড ডাটা: প্রমাণ-ভিত্তিক আসল অভিযোগ /admin দিয়ে যাচাই করে প্রকাশ করুন।
  ডাটাবেজ খালি রেখে লঞ্চ করবেন না — প্রথম ব্যবহারকারীর আস্থাই সব।
- কোনো নমুনা/ভুয়া নম্বর কখনো সিড হিসেবে দেবেন না — প্রতিটি প্রকাশিত অভিযোগের
  পেছনে আসল প্রমাণ থাকতে হবে।
